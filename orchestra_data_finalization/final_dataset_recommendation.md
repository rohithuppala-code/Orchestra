# Final Dataset Recommendation for ORCHESTRA

> **Decision:** SILO-BENCH is adopted as ORCHESTRA's primary and sole benchmark.
> No external dataset acquisition is necessary.

---

## 1. The Decision

**SILO-BENCH is sufficient.** We will:

1. **Reuse** all 180 benchmark files and the full execution framework as-is.
2. **Generate** behavioral data by running experiments when the ORCHESTRA architecture and experimental protocol are finalized.
3. **Add minimal instrumentation** to the execution framework for organizational structure analysis.
4. **Not acquire** any additional external dataset.

### Rationale

SILO-BENCH is purpose-built for exactly the setting ORCHESTRA studies: autonomous agents with private information, no pre-assigned roles, multiple communication protocols, and scalable agent counts. The benchmark's role-free design (verified in [`src/utils/prompts.py` L272-292](file:///c:/Users/sairo/OneDrive/Documents/UROP/silo-bench/src/utils/prompts.py#L272-L292)) means any organizational structure that appears during experiments is necessarily emergent — which is ORCHESTRA's core research question.

No other publicly available benchmark simultaneously provides:
- Role-free multi-agent coordination tasks
- 2–100 agent scalability
- Three distinct communication protocol variants
- Complete per-round, per-agent logging infrastructure
- Ground-truth expected outputs for quantitative evaluation

## 4. Minimal Instrumentation Needed for ORCHESTRA

The existing framework logs enough raw data, but ORCHESTRA requires post-processing tools that do not yet exist. These should be built as a **separate analysis layer** — not by modifying the SILO-BENCH source code.

### 4.1 Must-Have (Before First Experiments)

| Tool | Purpose | Input | Output |
|---|---|---|---|
| **Communication graph extractor** | Build directed graph per round from message logs | `rounds/round-N/env/messages/*.json` | NetworkX graph objects or edge lists |
| **Role classifier** | Classify agents into behavioral roles based on tool usage patterns | `logs/agent-NNN.jsonl` | Per-agent role labels per round |
| **Topology comparator** | Compare emergent topology against `metadata.optimal_topology` | Extracted graph + benchmark JSON | Topological fidelity score |

### 4.2 Nice-to-Have (Can Be Added Incrementally)

| Tool | Purpose | Depends On |
|---|---|---|
| Agent dropout simulator | Skip specific agents in specific rounds | Modify `engine.py` `run_round()` loop |
| Message drop simulator | Probabilistically fail message delivery | Modify protocol `tools.py` |
| Prompt variant generator | Create task descriptions without topology hints | Generate modified benchmark JSONs |
| Cross-task memory | Persistent agent context across sequential tasks | New orchestration layer |

### 4.3 Not Needed

| Unnecessary Item | Reason |
|---|---|
| Vector database / embeddings | Task search is not a research objective; 180 files are easily browsable |
| Additional external datasets | SILO-BENCH covers the needed coordination complexity gradient |
| Custom LLM fine-tuning | ORCHESTRA studies emergent behavior, not model training |
| Web dashboard / API | Focus is on batch experiments and analysis scripts |
| Benchmark data preprocessing | JSON files are loaded directly by existing `engine.py` |

## 5. Known Limitations (Must Be Disclosed in Paper)

### 5.1 Coordination Hints in Task Descriptions

Task descriptions include algorithmic guidance and optimal topology suggestions. This means agents are *informed* about the intended coordination pattern. While they may deviate, this creates a bias toward the suggested structure. **Mitigation:** Run experiments with and without hints as an independent variable.

### 5.2 Synchronous Round-Based Communication

All protocols use strict round-based synchronization (messages from round *t* visible in round *t+1*). Real organizational communication is asynchronous. The discrete-time model may suppress certain organizational dynamics. **Mitigation:** Acknowledge as an environmental constraint; future work could explore asynchronous variants.

### 5.3 No Agent Memory Across Tasks

Each experiment starts fresh. Agents cannot learn from previous tasks. Studying *organizational evolution* (how structures improve over time) requires a multi-task experimental protocol not currently supported. **Mitigation:** Build a thin orchestration layer that chains experiments and carries forward a "lessons learned" prompt.

### 5.4 Fixed Agent Count During Execution

Agents cannot join or leave during a task. Studying organizational resilience requires framework modifications. **Mitigation:** Implement agent dropout as described in §4.2 when needed.

### 5.5 LLM API Cost

Running the full experimental matrix (2,700 experiments × multiple rounds × multiple agents) requires significant API budget. Costs depend on model choice and agent scale. Start with small scales (n=2, n=5) and cheaper models to validate the pipeline before scaling up.

## 6. Answers to the Acceptance Questions

### Q1: What exact benchmark and task files will ORCHESTRA use?

All 180 files in `silo-bench/benchmarks/` matching the pattern `{I,II,III}-{01..30}_n{2,5,10,20,50,100}.json`. The summary index `benchmark_summary.json` will be used for task metadata lookup. The aggregated `silo_bench_full.json` will not be used (individual files are more practical).

### Q2: Is SILO-BENCH sufficient as the primary task benchmark?

**Yes.** Its role-free design, three complexity levels, three communication protocols, and 2–100 agent scaling provide a comprehensive testbed for ORCHESTRA's research questions. No critical gap requires an external dataset.

### Q3: What data is already available, and what must be generated later?

**Available now:** 180 task definitions with input shards, expected outputs, optimal topologies, complexity classifications, and the complete execution/evaluation framework.

**Must be generated later:** All behavioral data — agent interaction logs, communication graphs, emergent topologies, performance metrics — by running experiments through the existing framework with an LLM API.

### Q4: What minimal data preparation or instrumentation will eventually be necessary?

Three analysis tools (communication graph extractor, role classifier, topology comparator) must be built as post-processing scripts. These read the existing log format and do not require modifying the SILO-BENCH codebase. Optional framework modifications (agent dropout, message failure simulation) can be added later for perturbation studies.

### Q5: Can we finalize the dataset plan without acquiring another external dataset?

**Yes.** SILO-BENCH is the complete dataset foundation. The plan is:
1. Use existing benchmark files as task definitions *(now)*
2. Build post-processing analysis tools *(before first experiments)*
3. Run experiments to generate behavioral data *(after ORCHESTRA architecture is finalized)*
4. Analyze emergent organizational patterns from the logs *(iterative research process)*
